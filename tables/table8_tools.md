# Table 8 — Software Components and Reproducibility Records

Tools are listed by pipeline stage and link to their official sites. Availability does not imply that a pipeline has been reproduced.

| Stage | Tool | Inputs and outputs | Role | License | Record |
|---|---|---|---|---|---|
| Registration | [SimpleITK](https://simpleitk.org/) | Images and masks; aligned images and transforms. | Align CT-MRI pairs and resample onto a shared physical grid. | Apache 2.0 | Save transform direction, reference grid, interpolation, optimizer settings and registration checks. |
| \midrule Registration | [ANTs](https://github.com/ANTsX/ANTs) | Image volumes; affine transforms and deformation fields. | Provide an alternative registration and MRI bias-correction component. | Apache 2.0 | Save command lines, masks, transform order, similarity metric and parameter files. |
| \midrule ROI and display | [3D Slicer](https://www.slicer.org/) | Volumes, labels and transforms; scenes, masks and views. | Inspect alignment, edit ROIs and review source images alongside fused outputs. | BSD-style Slicer license | Save scene, extension versions, ROI edits, display windows and overlay settings; viewing alone is not clinical validation. |
| \midrule Data preparation | [MONAI](https://github.com/Project-MONAI/MONAI) | Images and metadata; transformed tensors and batches. | Compose medical-image loading, caching and synchronized spatial transforms. | Apache 2.0 | Save dataset manifest, transform order, reader options, channel order, spacing, normalization and seeds. |
| \midrule Data preparation | [TorchIO](https://github.com/TorchIO-project/torchio) | Subject images and labels; transformed volumes and patches. | Prepare corresponding 3D inputs and apply shared spatial augmentation. | Apache 2.0 | Save subject definitions, sampling policy, transform parameters and random states; verify paired geometry. |
| \midrule Algorithm development | [MATLAB Image Processing Toolbox](https://www.mathworks.com/products/image-processing.html) | Arrays and images; processed images and metric values. | Support image processing and prototype fusion rules supplied by the researcher. | Commercial | Save MATLAB/toolbox versions and scripts; identify any additional transform or fusion-metric code and its license. |
| \midrule Training | [PyTorch](https://github.com/pytorch/pytorch) | Tensors and model code; weights and predictions. | Implement the chosen fusion architecture, losses, training and inference. | BSD-3-Clause | Save code revision, environment, model configuration, checkpoint hash, seeds, device and determinism settings. |
| \midrule Training | [PyTorch Lightning](https://github.com/Lightning-AI/pytorch-lightning) | PyTorch models and data modules; checkpoints and logs. | Organize training loops and distributed execution. | Apache 2.0 | Save Trainer settings, callbacks, precision, strategy, resume state and data-loader configuration. |
| \midrule Training | [TensorFlow / Keras](https://www.tensorflow.org/) | Tensors and model definitions; saved models and predictions. | Provide an alternative framework for a specified fusion model. | Apache 2.0 | Save architecture, weights, preprocessing, dependency versions, training settings and export signature. |
| \midrule Metrics | [scikit-image](https://scikit-image.org/docs/stable/api/skimage.metrics.html) | Source/output arrays; PSNR, SSIM and other implemented metrics. | Compute specified image-quality measures with an explicit reference convention. | BSD-3-Clause; bundled exceptions | Save function/version, data range, window settings, channel handling, masks and per-case values. |
| \midrule Metrics | [TorchMetrics](https://github.com/Lightning-AI/torchmetrics) | Prediction/target tensors; metric states and summaries. | Evaluate supported image or downstream-task metrics within tensor workflows. | Apache 2.0 | Save exact metric class, arguments, reduction and distributed aggregation; verify any custom fusion metric separately. |
| \midrule Tracking | [TensorBoard](https://github.com/tensorflow/tensorboard) | Event logs; scalar curves and image summaries. | Track training and inspect corresponding source/output samples. | Apache 2.0 | Archive event files with run identifiers and configurations; dashboards do not replace data manifests or scripts. |
| \midrule Export | [ONNX](https://github.com/onnx/onnx) | Supported model graphs; portable graph files. | Exchange a trained fusion model between compatible runtimes. | Apache 2.0 | Record exporter/opset, input names and shapes; check output agreement against the source framework. |
| \midrule Inference | [TensorRT](https://developer.nvidia.com/tensorrt) | Supported models; optimized inference engines. | Optimize inference on supported NVIDIA GPUs. | NVIDIA SDK terms; OSS parts Apache 2.0 | Save runtime/hardware versions, precision, shape profiles and calibration data; measure export-related output changes. |
| \midrule Inference | [OpenVINO](https://github.com/openvinotoolkit/openvino) | Supported models; converted models and runtime outputs. | Execute and optimize inference on supported hardware. | Apache 2.0 | Save conversion options, device, precision and runtime version; verify outputs and measure complete-pipeline latency. |
| \midrule Packaging | [MONAI Deploy App SDK](https://github.com/Project-MONAI/monai-deploy-app-sdk) | Application operators and models; packaged applications. | Connect configured image readers, inference and output writers. | Apache 2.0 | Save application graph, package version, series-selection rules, metadata mapping and end-to-end checks. |
| \midrule Packaging | [Docker Engine](https://docs.docker.com/engine/) | Build recipes and dependencies; container images. | Package the selected preprocessing, inference and evaluation environment. | Apache 2.0; Desktop terms separate | Archive Dockerfile, dependency locks, image digest, mounts, command and host/GPU details; containers do not fix missing data or protocols. |
